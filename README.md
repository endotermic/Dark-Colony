# Dark-Colony
Dark Colony - real time strategy released in 1997

Repository contains:
1) working copy of the original game
2) working copy of standalone expansion pack
3) working copy of map editor
4) the patch tools (`patch_resolution.py`, `patch_cursor.py`, `hud_layout.py`, `pad_background.py`, `spr.py`, `logo_art.py`, `paint_intro.py`) and the reverse-engineering notes (`DC16_BATTLE_ENGINE.md`, `DC16_DISPLAY_AND_RESOLUTION.md`) live in the sister repository [Dark-Colony-Server](https://github.com/endotermic/Dark-Colony-Server) since 10 Sep 2026: [`tools/`](https://github.com/endotermic/Dark-Colony-Server/tree/main/tools) and [`docs/`](https://github.com/endotermic/Dark-Colony-Server/tree/main/docs), next to the network-protocol notes and the relay server. This repository keeps only the game files. The tools take the game directory or executable as an argument, e.g. `python ../Dark-Colony-Server/tools/patch_cursor.py verify "DC - Council wars/Dark Colony.exe"`.

**Since 15 Sep 2026 both games run from the one folder `DC - Council wars/`** (its root is the complete Classic data set, the expansion lives in `exp/`): the untouched Classic exe is `DC - Council wars/dc16.exe`, its patched build `DC - Council wars/Dark Colony.exe`; the Council Wars pair is `ENGEXP16.EXE` / `Dark Colony Ultimate.exe` (Council Wars plus the Dark Colony, OZI and Academy campaigns in its menu); the map editor pair is `Dark Colony - Map editor/maped.exe` / `Dark Colony Map Editor.exe`. **The patched builds were renamed on 25 Sep 2026** - until then `dc16new.exe`, `engexp16new.exe` and `maped_ozi_ns_v1.2.exe` (git history follows the renames) - and since then all three carry a high-resolution icon (`DC - Council wars/DC_HD.ICO`, re-drawn from the game's own 32x32 `DC.ICO`). Everything the `DC - Classic/` folder held (the folder itself was removed on 15 Sep 2026; its history stays in git) is in the Council Wars folder as well - the Classic briefings `MISSION/`, the `ENCYCLO/` unit encyclopedia, the wallpapers, the map tool `SCENARIO/MPLAYER/PMAP.EXE`, the older map revisions `SCENARIO/MULTI-~1/`, and the Classic movies whose names clash with Council Wars' own as `AVI/DCINTRO.AVI`, `AVI/DCAENDING.AVI`, `AVI/DCHENDING.AVI` (`Dark Colony.exe` plays them, fix "Classic movies under their own names"; the untouched Classic exe plays Council Wars' `INTRO.AVI` and endings there, and - because its sound loader looks under `exp/` first - the Council Wars briefings for missions 1-8; `Dark Colony.exe` plays the Classic ones since 19 Sep 2026, fix `sounds`). The map editor stays in its own folder `Dark Colony - Map editor/` (its `maped.exe` is byte-identical to `DC\MAPED.EXE` on the Dark Colony CD; the Council Wars CD carries no editor). Since 15 Sep 2026 that folder also holds **`Dark Colony Map Editor.exe`**, built by the patcher from `maped.exe`: the ozi_ns editor (`maped_by_ozy_ns_v1.2PL.exe`) turned out to contain no code change at all - its code, imports and relocations are byte-identical to the original - only a Polish translation, an icon, a new title and one functional thing: the "disabled" flag cleared on dialog controls the original greyed out (the Atlantis / Training / Special block-set buttons of New Map, the Team Colour and Allies groups of Team Attributes, the Healer row of Troop Attributes, plus a close box on that dialog). `Dark Colony Map Editor.exe` was exactly those 24 one-byte unlocks on the English original until 1 Oct 2026; **since then it un-greys everything the editor ships greyed out** (79 one-byte resource edits, no code): the AI Type and AI Slots fields of Team Attributes, the Campaign scenario type, the File menu's Super Gen / Load MED / Save MED (the editor's own document format and the developers' batch export), the Block Type menu, the City State and Troop Attributes dialogs (their menu entries had no handler - they are re-pointed to the two command ids the dialogs listen to), the two Leutenant entries, the six single artifacts, the Lights menu, the Trigger tool with Edit Trigger String, and the Flag tool with the AI Flags menu (a dead feature: the game has no flag object, a placed flag becomes a player-0 mining tower - leave that fix unticked unless experimenting). The unchanged code already handles every control; the one entry left greyed, Edit Text, has no code path at all. Why each control was greyed: `docs/DC16_MAP_FILES.md` section 13 in Dark-Colony-Server. The three block sets need `scenario\atlantis.set`, `trainh.set`, `special.set` and `special.bts` next to the editor; the editor says "Can't open file" without them. Since 15 Sep 2026 the editor folder ships **`scenario\atlantis.set`** (828 prefab blocks generated from the eleven existing Atlantis maps by `tools/blockset.py` in Dark-Colony-Server, every tile checked against `ATLANTIS.BTS`) with `scenario\atlantis.bts`, so New Map -> Atlantis works out of the box; Training and Special still need the ozi_ns pack files. The untouched Classic exe needs its CD: a CD image with a `/DC/` tree mounted on the drive named in `HBNFUFL.A01` (the Council Wars image has one).

5) the untouched original executables: `DC - Council wars/dc16.exe` (the dc16.exe of the January 1998 update, the build every patch here is based on; until 15 Sep 2026 it was `DC - Classic/dc16original1998.exe`) and `DC - Council wars/ENGEXP16.EXE` (from the Council Wars CD). Since 14 Sep 2026 they **run out of the box beside the patched exes**: the stock 640x480 menus, HUD and briefing lists are back under their original names in `INTRFACE/`, `GAMESTAT/` and `SPRITES/`, the 1024x768 versions live under the same names in `INTRF_HD/` (Council Wars also `exp/intrf_hd/`, `ozi_ns/intrf_hd/`) with the re-baked logo sprites as `SPRITES/*_HD.SPR`, and the patched exes read `intrf_hd/...` for exactly those files (30 path strings, the "Interface data from INTRF_HD" fix). The originals still look for the CD, and the original Council Wars exe without its disc greys main-menu buttons that its own menu script never defines and dies on an assert (`widget.c` line 152, hidden behind the full screen) - the shipped game did the same. A CD-free 640x480 build is one patcher command away and runs beside the 1024x768 exes: `Apply-DarkColonyPatches.ps1 -Original <original> -Patches nocd` (the one CD fix: the 2025 bypass bytes plus the removal of the whole CD path, so the build also works on PCs where drive D: is a card reader, an empty DVD drive or a sleeping disk). Such special builds are not committed; the repository ships the originals and the fully patched exes only. Council Wars' own 640x480 menu backdrops `exp/intrface/intrg.gif` / `intro.gif` come from the CD (they were missing from the install the folder was copied from). **Every file the original exes read is byte-identical to the CD** (checked against the whole `/EXPENG/` tree of the Council Wars CD; the OZI pack's additions live under their own names `exp/animozi.dat`, `exp/animate/tranozi.fin`, `exp/sprites/tranozi.spr`). To run the untouched original itself, mount the Council Wars CD image so that it becomes drive `D:` (the letter in `hbnfufl.a02`): the game checks that `D:\dc\anim.dat` exists and that the drive refuses writes. A `.bin` image has to be converted to `.iso` first (data track only) - Windows mounts `.iso` files with a double-click
6) `Apply-DarkColonyPatches.ps1` - see the next section; step-by-step instructions for players in [`PATCH_HOWTO.TXT`](PATCH_HOWTO.TXT)

## Playing online: ONLINE WAR

`Dark Colony Ultimate.exe` has an **ONLINE WAR** button at the top of the main menu's right column
(since 29 Sep 2026). It reads the relay's address from **`DC - Council wars/DEFAULT_SERVER.TXT`**
(plain text with C++-style comments; it ships with `dark-colony-server.fly.dev`), connects to it with
TLS on port 8889, shows the rooms the relay offers - map, terrain, seats, players, bots, status - and
joins the room you pick; the relay chooses a free slot for you and the usual lobby follows. To use
another relay edit that file (`host[:port]`, and the word `plain` after the address for a LAN relay
without a certificate, which then uses the plain port 8888). `ONLINE.LOG` beside the exe records each
step of a connection attempt. MULTI PLAYER WAR (the in-game host and CONNECT TO SERVER screens) is
unchanged. The server side is the sister repository [Dark-Colony-Server](https://github.com/endotermic/Dark-Colony-Server).

## Are the patched executables safe? Build them yourself

`Dark Colony Ultimate.exe` and `Dark Colony Map Editor.exe` in this repository are the original 1997/98 binaries with a handful of byte patches (no CD check, 1024x768, cursor fix, 150 % default game speed, the dark console-style battlefield interface, ...). **The patched Classic `Dark Colony.exe` is deprecated and no longer shipped since 1 Oct 2026** (the untouched original `dc16.exe` stays): `Dark Colony Ultimate.exe` plays the whole Dark Colony campaign (DARK COLONY / LOAD DC GAME / ACADEMY in its main menu) with every fix, so the separate Classic executable is no longer needed; the patcher writes it only on request - the checkbox on its options page, `-IncludeDeprecated`, or `-Original "DC - Council wars\dc16.exe"` on the command line. A hand-modified exe cannot be signed and some antivirus heuristics dislike it, so the whole modification is made transparent and reproducible by one file, `Apply-DarkColonyPatches.ps1`, in the root of this repository:

- it is a plain PowerShell script; open it in any text editor and read it. It needs nothing but Windows itself (Windows PowerShell 5.1 or PowerShell 7) - no Python, no downloads, no external tools, no network access
- every fix is a list of byte edits written out as data: file offset, old bytes, new bytes and the reason for the change, with a paragraph explaining what the fix does and where it is documented
- it never modifies the input file; it writes a new file. A byte is written only if the original still holds the documented old bytes at that offset
- with every fix selected at 1024x768 with the dark interface the result is **byte-identical** to the `Dark Colony Ultimate.exe` / `Dark Colony Map Editor.exe` committed here, and the script tells you so by comparing the SHA-256
- the screen resolution is chosen **once, explicitly** - the first page of the window (nothing is preselected; `640x480 (original)` is the game as it shipped) or `-Resolution` on the command line, which is required for the games. Everything the size changes is **one fix per size** (`resolution`: screen mode, the `INTRF_HD` path strings and the clock hand; until 1 Oct 2026 three fixes that only worked together), and applying it writes the `INTRF_HD` interface set for that size into the game folder
- the **battlefield interface** is chosen with the resolution, also explicitly (two radio buttons, none preselected; `-Theme light|dark` on the command line, required at an HD size): **light (classic)** = the original brushed-metal HUD, dialogs and clock dial, from the shipped metal frame `INTRF_HD/<WxH>/INTRFACE_LIGHT.GIF` and the stock banks; **dark** = the console style of the menus drawn on 28-30 Sep 2026 (`INTRFACE.GIF`, the `INTRF_HD` banks, the console dialog layouts) plus the one-edit fix `console` that points the exe at the redrawn clock dial `SPRITES/CLOCK.SPR`. Not asked at 640x480, where the game keeps its own interface. The committed executables are the dark 1024x768 build
- **since 2 Oct 2026 every resolution's interface set lives in its own folder** - `HD_0768P` (1024x768), `HD_0720P`, `HD_0800P`, `HD_1024P`, `HD_1080P`, `HD_1200P`, `UW_1080P` / `UW_1440P` for the ultra-wide sizes (8 characters: the exe's path strings are rewritten in place, `hd_1080p/bintro`; the Council Wars copies in `exp/`, `dc/`, `ozi_ns/` follow). The repository ships the 1024x768 set in `HD_0768P/` and the patcher's inputs in `HD_SRC/` (the five pictures per size, the two console banks). **A patcher run deletes every other resolution's folder** (and the pre-October `INTRF_HD/`, and the 640x480 copies when building an HD size) before it writes, so no file of another size is left anywhere - a HUD script of one size can no longer sit under the frame of another (the "interface elements are not in place" report).
- it checks that the resources each fix needs are next to the output (the shipped pictures in `HD_SRC/<WxH>/`, the `_HD` sprites, `AVI/DCINTRO.AVI` / `DCAENDING.AVI` / `DCHENDING.AVI` for the Classic movies, the `ozi_ns/` overlay and `exp/animozi.dat` for OZI MISSIONS). A fix whose resources are missing, or which depends on such a fix, is shown as `[RESOURCES NOT FOUND]`: its checkbox cannot be ticked, "Select all" skips it, and `-All` on the command line skips it with a message. An exe patched into a folder without those files would fail at start-up or draw the menus into a corner, which would look like a bug of the patch. Every fix lists its files (`-List -Detail`); `-IgnoreMissingData` overrides the check from the command line

How to use it (plain-text walkthrough for beginners: [`PATCH_HOWTO.TXT`](PATCH_HOWTO.TXT)): double-click **`INSTALL.CMD`** in the repository root. It is a short, commented starter that runs the `.ps1` beside it with Windows PowerShell 5.1 and `-ExecutionPolicy Bypass` for that one run (Windows' own *Run with PowerShell* obeys the execution policy, which refuses a script from a downloaded ZIP or, on many PCs, every script; no setting of the PC is changed). Windows may warn once that the file comes from the internet: *More info* -> *Run anyway*, or *Run*. An installer opens - *Welcome* -> *Options* -> *Dark Colony Ultimate* -> *Dark Colony Map Editor* (-> *Dark Colony*, only when asked for) -> *Ready to patch* -> *Finished*, with *< Back* / *Next >* / *Cancel*. The welcome page lists the three originals it **found beside the script** (`DC - Council wars/ENGEXP16.EXE`, `Dark Colony - Map editor/maped.exe`, `DC - Council wars/dc16.exe`) and offers the desktop shortcuts (ticked). The options page has the screen resolution in a drop-down (`640x480 (original)`, `1024x768 (4:3)`, ... `3840x1080 (32:9)`, the sizes with your monitor's aspect ratio marked *recommended for your screen*), under it the battlefield interface (*Light (classic)* / *Dark*, live at the HD sizes) and under it the checkbox *Also patch the deprecated Dark Colony* - **nothing preselected**: *Next >* stays disabled until the size and, at an HD size, the interface are chosen, once, for both games (they share `INTRF_HD`); the Dark Colony page exists only while its box is ticked. Each executable page has "Patch <name>" (ticked), the original with its own *Browse* button, the chosen resolution and interface, the fix checklist with *Select all fixes* and the description of the highlighted fix; the *Ready to patch* page sums up what will be written (files, fixes, interface set, shortcuts, skipped executables) before anything is. An original that is missing, already patched, changed or no Dark Colony exe at all puts a **big red box** on its page (and a red banner on the welcome page) with what was found and what is expected, *Select the correct file...*, *Download from our repository* (opens the file's GitHub page; the script downloads nothing) and where the original disc has it (`EXPENG\ENGEXP16.EXE` on the Council Wars CD, `DC\MAPED.EXE` on the Dark Colony CD; the Dark Colony CD's `DC16.EXE` is the August 1997 build, the fixes need the January 1998 update from the repository); that executable stays unpatched until the right file is chosen. So the options once, *Next >* through the pages and *Patch* once writes `Dark Colony Ultimate.exe` and `Dark Colony Map Editor.exe` (and `Dark Colony.exe` if you asked for it) beside the originals, and a shortcut of the same name to each on the desktop, starting in its game folder. *Inspect an exe* tells you which fixes any executable carries. Without the starter, from a PowerShell prompt in the repository folder:

```
powershell -ExecutionPolicy Bypass -File .\Apply-DarkColonyPatches.ps1
```

Command line, for the record (the same options work through the starter, e.g. `INSTALL.CMD -List`): `-All -Resolution 1024x768 -Theme dark [-DesktopShortcut] [-IncludeDeprecated]` (Dark Colony Ultimate and the map editor, like the window; `-IncludeDeprecated` adds Dark Colony), `-Original <exe> -All -Resolution <WxH> -Theme light|dark`, `-Original <exe> -Resolution 640x480 -Patches nocd`, `-List -Detail` (every single byte edit), `-Verify <exe>`; `-Resolution` is required for the games and `-Theme` at an HD size (no defaults), relative paths are taken from the current folder.

The fixes, in the order the script applies them: no CD (`nocd`: the 2025 bypass of the two menu tests - and, in Council Wars, of a third test that threw the player out of a running game - plus, since 18 Sep 2026, the removal of the whole CD path: the bypass alone only ignored the answer of the CD test, the game still read the drive letter from `HBNFUFL.A01`/`.A02`, opened `D:\dc\anim.dat` and ran a write test there at start-up, at every menu screen and in game, fell back to `D:\dc\<file>` for missing files and asked to "insert the CD", and it never asks Windows to fail such accesses quietly, so a not-ready drive D: - a card reader or USB/optical drive without a medium, a sleeping second hard disk - showed Windows' "No Disk" box behind the full-screen game or stalled it; not applied at 640x480), the dark battlefield interface (`console`, 28-30 Sep 2026, a choice since 1 Oct 2026: the console-style HUD, dialogs and clock dial of the menus' visual language - data written with the interface set plus one 14-byte edit, the dial bank name `sprites/cloc` -> `sprites/clock`; its data also carries, since 2 Oct 2026, the **tracer bullets**: the human trooper and the Lieutenant fire a visible yellow streak - the stock table named a projectile sprite that no animation bank defines - and the Gray trooper keeps its glowing bolt at every weapon upgrade level instead of losing it after the first one, the Gray commander's pistol fires that bolt too; data only, in sync with unpatched players). The third build the script knows is the map editor: `Dark Colony - Map editor\maped.exe` -> `Dark Colony Map Editor.exe` (until 25 Sep 2026 `maped_ozi_ns_v1.2.exe`) with fourteen fixes (15 Sep 2026: block sets, team colour and allies, Healer row, close box; 1 Oct 2026: AI type and slots, Campaign type, MED files and Super Gen, Block Type menu, City State and Troop Attributes dialogs, Leutenants, artifacts, Lights, Trigger tool, Flag tool), all dialog- and menu-resource bytes, no code.
