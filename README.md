# Dark-Colony
Dark Colony - real time strategy released in 1997

Repository contains:
1) working copy of the original game
2) working copy of standalone expansion pack
3) working copy of map editor
4) the patch tools (`patch_resolution.py`, `patch_cursor.py`, `hud_layout.py`, `pad_background.py`, `spr.py`, `logo_art.py`, `paint_intro.py`) and the reverse-engineering notes (`DC16_BATTLE_ENGINE.md`, `DC16_DISPLAY_AND_RESOLUTION.md`) live in the sister repository [Dark-Colony-Server](https://github.com/endotermic/Dark-Colony-Server) since 10 Sep 2026: [`tools/`](https://github.com/endotermic/Dark-Colony-Server/tree/main/tools) and [`docs/`](https://github.com/endotermic/Dark-Colony-Server/tree/main/docs), next to the network-protocol notes and the relay server. This repository keeps only the game files. The tools take the game directory or executable as an argument, e.g. `python ../Dark-Colony-Server/tools/patch_cursor.py verify "DC - Council wars/dc16new.exe"`.

**Since 15 Sep 2026 both games run from the one folder `DC - Council wars/`** (its root is the complete Classic data set, the expansion lives in `exp/`): the untouched Classic exe is `DC - Council wars/dc16.exe`, its patched build `DC - Council wars/dc16new.exe`; the Council Wars pair is `ENGEXP16.EXE` / `engexp16new.exe`. Everything the `DC - Classic/` folder held (the folder itself was removed on 15 Sep 2026; its history stays in git) is in the Council Wars folder as well - the Classic briefings `MISSION/`, the `ENCYCLO/` unit encyclopedia, the wallpapers, the map tool `SCENARIO/MPLAYER/PMAP.EXE`, the older map revisions `SCENARIO/MULTI-~1/`, and the Classic movies whose names clash with Council Wars' own as `AVI/DCINTRO.AVI`, `AVI/DCAENDING.AVI`, `AVI/DCHENDING.AVI` (`dc16new.exe` plays them, fix "Classic movies under their own names"; the untouched Classic exe plays Council Wars' `INTRO.AVI` and endings there). The map editor stays in its own folder `Dark Colony - Map editor/` (its `maped.exe` is byte-identical to `DC\MAPED.EXE` on the Dark Colony CD; the Council Wars CD carries no editor). Since 15 Sep 2026 that folder also holds **`maped_ozi_ns_v1.2.exe`**, built by the patcher from `maped.exe`: the ozi_ns editor (`maped_by_ozy_ns_v1.2PL.exe`) turned out to contain no code change at all - its code, imports and relocations are byte-identical to the original - only a Polish translation, an icon, a new title and one functional thing: the "disabled" flag cleared on dialog controls the original greyed out (the Atlantis / Training / Special block-set buttons of New Map, the Team Colour and Allies groups of Team Attributes, the Healer row of Troop Attributes, plus a close box on that dialog). `maped_ozi_ns_v1.2.exe` is exactly those 24 one-byte unlocks on the English original; the unchanged code already handles every control. The three block sets need `scenario\atlantis.set`, `trainh.set`, `special.set` and `special.bts` next to the editor; the editor says "Can't open file" without them. Since 15 Sep 2026 the editor folder ships **`scenario\atlantis.set`** (828 prefab blocks generated from the eleven existing Atlantis maps by `tools/blockset.py` in Dark-Colony-Server, every tile checked against `ATLANTIS.BTS`) with `scenario\atlantis.bts`, so New Map -> Atlantis works out of the box; Training and Special still need the ozi_ns pack files. The untouched Classic exe needs its CD: a CD image with a `/DC/` tree mounted on the drive named in `HBNFUFL.A01` (the Council Wars image has one).

5) the untouched original executables: `DC - Council wars/dc16.exe` (the dc16.exe of the January 1998 update, the build every patch here is based on; until 15 Sep 2026 it was `DC - Classic/dc16original1998.exe`) and `DC - Council wars/ENGEXP16.EXE` (from the Council Wars CD). Since 14 Sep 2026 they **run out of the box beside the patched exes**: the stock 640x480 menus, HUD and briefing lists are back under their original names in `INTRFACE/`, `GAMESTAT/` and `SPRITES/`, the 1024x768 versions live under the same names in `INTRF_HD/` (Council Wars also `exp/intrf_hd/`, `ozi_ns/intrf_hd/`) with the re-baked logo sprites as `SPRITES/*_HD.SPR`, and the patched exes read `intrf_hd/...` for exactly those files (30 path strings, the "Interface data from INTRF_HD" fix). The originals still look for the CD, and the original Council Wars exe without its disc greys main-menu buttons that its own menu script never defines and dies on an assert (`widget.c` line 152, hidden behind the full screen) - the shipped game did the same. A CD-free 640x480 build is one patcher command away and runs beside the 1024x768 exes: `Apply-DarkColonyPatches.ps1 -Original <original> -Patches cdcheck` (2 resp. 3 bytes). Such special builds are not committed; the repository ships the originals and the fully patched exes only. Council Wars' own 640x480 menu backdrops `exp/intrface/intrg.gif` / `intro.gif` come from the CD (they were missing from the install the folder was copied from). **Every file the original exes read is byte-identical to the CD** (checked against the whole `/EXPENG/` tree of the Council Wars CD; the OZI pack's additions live under their own names `exp/animozi.dat`, `exp/animate/tranozi.fin`, `exp/sprites/tranozi.spr`). To run the untouched original itself, mount the Council Wars CD image so that it becomes drive `D:` (the letter in `hbnfufl.a02`): the game checks that `D:\dc\anim.dat` exists and that the drive refuses writes. A `.bin` image has to be converted to `.iso` first (data track only) - Windows mounts `.iso` files with a double-click
6) `Apply-DarkColonyPatches.ps1` - see the next section; step-by-step instructions for players in [`PATCH_HOWTO.TXT`](PATCH_HOWTO.TXT)

## Are the patched executables safe? Build them yourself

`dc16new.exe` and `engexp16new.exe` in this repository are the original 1997/98 binaries with a handful of byte patches (no CD check, 1024x768, cursor fix, ...). A hand-modified exe cannot be signed and some antivirus heuristics dislike it, so the whole modification is made transparent and reproducible by one file, `Apply-DarkColonyPatches.ps1`, in the root of this repository:

- it is a plain PowerShell script; open it in any text editor and read it. It needs nothing but Windows itself (Windows PowerShell 5.1 or PowerShell 7) - no Python, no downloads, no external tools, no network access
- every fix is a list of byte edits written out as data: file offset, old bytes, new bytes and the reason for the change, with a paragraph explaining what the fix does and where it is documented
- it never modifies the input file; it writes a new file. A byte is written only if the original still holds the documented old bytes at that offset
- with every fix selected the result is **byte-identical** to the `dc16new.exe` / `engexp16new.exe` committed here, and the script tells you so by comparing the SHA-256
- it checks that the resources each fix needs are next to the output (`INTRF_HD/` and the `_HD` sprites for 1024x768, `AVI/DCINTRO.AVI` / `DCAENDING.AVI` / `DCHENDING.AVI` for the Classic movies, the `ozi_ns/` overlay and `exp/animozi.dat` for OZI MISSIONS). A fix whose resources are missing, or which depends on such a fix, is shown as `[RESOURCES NOT FOUND]`: its checkbox cannot be ticked, "Select all" skips it, and `-All` on the command line skips it with a message. An exe patched into a folder without those files would fail at start-up or draw the menus into a corner, which would look like a bug of the patch. Every fix lists its files (`-List -Detail`); `-IgnoreMissingData` overrides the check from the command line

How to use it (plain-text walkthrough for beginners: [`PATCH_HOWTO.TXT`](PATCH_HOWTO.TXT)): right-click `Apply-DarkColonyPatches.ps1` -> *Run with PowerShell* (or run it from a PowerShell prompt). A window opens: *Browse* to `DC - Council wars/dc16.exe` or `DC - Council wars/ENGEXP16.EXE`, tick the fixes you want (the first checkbox selects all of them), press *Apply selected fixes*. *Inspect an exe* tells you which fixes any executable carries. If Windows refuses to run scripts, start it once with

```
powershell -ExecutionPolicy Bypass -File .\Apply-DarkColonyPatches.ps1
```

Command line, for the record: `-Original <exe> -All`, `-Original <exe> -Patches cdcheck,resolution,pool`, `-List -Detail` (every single byte edit), `-Verify <exe>`.

The fixes, in the order the script applies them: no CD required (2025), 1024x768 display (9 Sep 2026), no CD path at all (18 Sep 2026; "no CD required" only ignored the answer of the CD test - the game still read the drive letter from `HBNFUFL.A01`/`.A02`, opened `D:\dc\anim.dat` and ran a write test there at start-up, at every menu screen and in game, fell back to `D:\dc\<file>` for missing files and asked to "insert the CD", and it never asks Windows to fail such accesses quietly, so a not-ready drive D: - a card reader or USB/optical drive without a medium, a sleeping second hard disk - showed Windows' "No Disk" box behind the full-screen game or stalled it; nine small edits per exe jump over the HBNFUFL/CD-path block, disable the probe and every CD fallback and replace the "insert the CD" message; the patched exes no longer need the `HBNFUFL` files), interface data from `INTRF_HD` (14 Sep; the 30 path strings that make the exe read the 1024x768 files from `INTRF_HD/` so the stock files stay usable by the original exe), Windows pointer stays hidden (10 Sep), local memory pool 32 MiB (10 Sep), default game speed 150 % (10 Sep), day/night clock hand re-anchored (13 Sep), two-monitor start-up hang fixed (13 Sep), for Dark Colony only the Classic movies under their own names (15 Sep; `dc16new.exe` plays `AVI/DCINTRO.AVI` and the campaign lists in `INTRF_HD/` name `DCAENDING.AVI` / `DCHENDING.AVI`, because Council Wars' own `INTRO/AENDING/HENDING.AVI` sit in the same folder), and for Council Wars only the OZI MISSIONS menu mode (10 Sep). The third build the script knows is the map editor: `Dark Colony - Map editor\maped.exe` -> `maped_ozi_ns_v1.2.exe` with four fixes (15 Sep 2026: block sets, team colour and allies, Healer row, close box), all dialog-resource bytes, no code. The 1024x768 fix needs the `INTRF_HD` fix and the rebuilt interface data that ships in this repository next to the exe. The script itself is generated from the Python patch tools in Dark-Colony-Server (`tools/gen_apply_script.py`), so it always matches the committed executables.
