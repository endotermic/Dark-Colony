# Dark-Colony
Dark Colony - real time strategy released in 1997

Repository contains:
1) working copy of the original game
2) working copy of standalone expansion pack
3) working copy of map editor
4) the patch tools (`patch_resolution.py`, `patch_cursor.py`, `hud_layout.py`, `pad_background.py`, `spr.py`, `logo_art.py`, `paint_intro.py`) and the reverse-engineering notes (`DC16_BATTLE_ENGINE.md`, `DC16_DISPLAY_AND_RESOLUTION.md`) live in the sister repository [Dark-Colony-Server](https://github.com/endotermic/Dark-Colony-Server) since 10 Sep 2026: [`tools/`](https://github.com/endotermic/Dark-Colony-Server/tree/main/tools) and [`docs/`](https://github.com/endotermic/Dark-Colony-Server/tree/main/docs), next to the network-protocol notes and the relay server. This repository keeps only the game files. The tools take the game directory or executable as an argument, e.g. `python ../Dark-Colony-Server/tools/patch_cursor.py verify "DC - Council wars/Dark Colony.exe"`.

**Since 15 Sep 2026 both games run from the one folder `DC - Council wars/`** (its root is the complete Classic data set, the expansion lives in `exp/`): the untouched Classic exe is `DC - Council wars/dc16.exe`, its patched build `DC - Council wars/Dark Colony.exe`; the Council Wars pair is `ENGEXP16.EXE` / `Dark Colony Ultimate.exe` (Council Wars plus the Dark Colony, OZI and Academy campaigns in its menu); the map editor pair is `Dark Colony - Map editor/maped.exe` / `Dark Colony Map Editor.exe`. **The patched builds were renamed on 25 Sep 2026** - until then `dc16new.exe`, `engexp16new.exe` and `maped_ozi_ns_v1.2.exe` (git history follows the renames) - and since then all three carry a high-resolution icon (`DC - Council wars/DC_HD.ICO`, re-drawn from the game's own 32x32 `DC.ICO`). Everything the `DC - Classic/` folder held (the folder itself was removed on 15 Sep 2026; its history stays in git) is in the Council Wars folder as well - the Classic briefings `MISSION/`, the `ENCYCLO/` unit encyclopedia, the wallpapers, the map tool `SCENARIO/MPLAYER/PMAP.EXE`, the older map revisions `SCENARIO/MULTI-~1/`, and the Classic movies whose names clash with Council Wars' own as `AVI/DCINTRO.AVI`, `AVI/DCAENDING.AVI`, `AVI/DCHENDING.AVI` (`Dark Colony.exe` plays them, fix "Classic movies under their own names"; the untouched Classic exe plays Council Wars' `INTRO.AVI` and endings there, and - because its sound loader looks under `exp/` first - the Council Wars briefings for missions 1-8; `Dark Colony.exe` plays the Classic ones since 19 Sep 2026, fix `sounds`). The map editor stays in its own folder `Dark Colony - Map editor/` (its `maped.exe` is byte-identical to `DC\MAPED.EXE` on the Dark Colony CD; the Council Wars CD carries no editor). Since 15 Sep 2026 that folder also holds **`Dark Colony Map Editor.exe`**, built by the patcher from `maped.exe`: the ozi_ns editor (`maped_by_ozy_ns_v1.2PL.exe`) turned out to contain no code change at all - its code, imports and relocations are byte-identical to the original - only a Polish translation, an icon, a new title and one functional thing: the "disabled" flag cleared on dialog controls the original greyed out (the Atlantis / Training / Special block-set buttons of New Map, the Team Colour and Allies groups of Team Attributes, the Healer row of Troop Attributes, plus a close box on that dialog). `Dark Colony Map Editor.exe` is exactly those 24 one-byte unlocks on the English original; the unchanged code already handles every control. The three block sets need `scenario\atlantis.set`, `trainh.set`, `special.set` and `special.bts` next to the editor; the editor says "Can't open file" without them. Since 15 Sep 2026 the editor folder ships **`scenario\atlantis.set`** (828 prefab blocks generated from the eleven existing Atlantis maps by `tools/blockset.py` in Dark-Colony-Server, every tile checked against `ATLANTIS.BTS`) with `scenario\atlantis.bts`, so New Map -> Atlantis works out of the box; Training and Special still need the ozi_ns pack files. The untouched Classic exe needs its CD: a CD image with a `/DC/` tree mounted on the drive named in `HBNFUFL.A01` (the Council Wars image has one).

5) the untouched original executables: `DC - Council wars/dc16.exe` (the dc16.exe of the January 1998 update, the build every patch here is based on; until 15 Sep 2026 it was `DC - Classic/dc16original1998.exe`) and `DC - Council wars/ENGEXP16.EXE` (from the Council Wars CD). Since 14 Sep 2026 they **run out of the box beside the patched exes**: the stock 640x480 menus, HUD and briefing lists are back under their original names in `INTRFACE/`, `GAMESTAT/` and `SPRITES/`, the 1024x768 versions live under the same names in `INTRF_HD/` (Council Wars also `exp/intrf_hd/`, `ozi_ns/intrf_hd/`) with the re-baked logo sprites as `SPRITES/*_HD.SPR`, and the patched exes read `intrf_hd/...` for exactly those files (30 path strings, the "Interface data from INTRF_HD" fix). The originals still look for the CD, and the original Council Wars exe without its disc greys main-menu buttons that its own menu script never defines and dies on an assert (`widget.c` line 152, hidden behind the full screen) - the shipped game did the same. A CD-free 640x480 build is one patcher command away and runs beside the 1024x768 exes: `Apply-DarkColonyPatches.ps1 -Original <original> -Patches nocd` (the one CD fix: the 2025 bypass bytes plus the removal of the whole CD path, so the build also works on PCs where drive D: is a card reader, an empty DVD drive or a sleeping disk). Such special builds are not committed; the repository ships the originals and the fully patched exes only. Council Wars' own 640x480 menu backdrops `exp/intrface/intrg.gif` / `intro.gif` come from the CD (they were missing from the install the folder was copied from). **Every file the original exes read is byte-identical to the CD** (checked against the whole `/EXPENG/` tree of the Council Wars CD; the OZI pack's additions live under their own names `exp/animozi.dat`, `exp/animate/tranozi.fin`, `exp/sprites/tranozi.spr`). To run the untouched original itself, mount the Council Wars CD image so that it becomes drive `D:` (the letter in `hbnfufl.a02`): the game checks that `D:\dc\anim.dat` exists and that the drive refuses writes. A `.bin` image has to be converted to `.iso` first (data track only) - Windows mounts `.iso` files with a double-click
6) `Apply-DarkColonyPatches.ps1` - see the next section; step-by-step instructions for players in [`PATCH_HOWTO.TXT`](PATCH_HOWTO.TXT)

## Are the patched executables safe? Build them yourself

`Dark Colony.exe`, `Dark Colony Ultimate.exe` and `Dark Colony Map Editor.exe` in this repository are the original 1997/98 binaries with a handful of byte patches (no CD check, 1024x768, cursor fix, ...). A hand-modified exe cannot be signed and some antivirus heuristics dislike it, so the whole modification is made transparent and reproducible by one file, `Apply-DarkColonyPatches.ps1`, in the root of this repository:

- it is a plain PowerShell script; open it in any text editor and read it. It needs nothing but Windows itself (Windows PowerShell 5.1 or PowerShell 7) - no Python, no downloads, no external tools, no network access
- every fix is a list of byte edits written out as data: file offset, old bytes, new bytes and the reason for the change, with a paragraph explaining what the fix does and where it is documented
- it never modifies the input file; it writes a new file. A byte is written only if the original still holds the documented old bytes at that offset
- with every fix selected the result is **byte-identical** to the `Dark Colony.exe` / `Dark Colony Ultimate.exe` / `Dark Colony Map Editor.exe` committed here, and the script tells you so by comparing the SHA-256
- it checks that the resources each fix needs are next to the output (`INTRF_HD/` and the `_HD` sprites for 1024x768, `AVI/DCINTRO.AVI` / `DCAENDING.AVI` / `DCHENDING.AVI` for the Classic movies, the `ozi_ns/` overlay and `exp/animozi.dat` for OZI MISSIONS). A fix whose resources are missing, or which depends on such a fix, is shown as `[RESOURCES NOT FOUND]`: its checkbox cannot be ticked, "Select all" skips it, and `-All` on the command line skips it with a message. An exe patched into a folder without those files would fail at start-up or draw the menus into a corner, which would look like a bug of the patch. Every fix lists its files (`-List -Detail`); `-IgnoreMissingData` overrides the check from the command line

How to use it (plain-text walkthrough for beginners: [`PATCH_HOWTO.TXT`](PATCH_HOWTO.TXT)): double-click **`INSTALL.CMD`** in the repository root. It is a short, commented starter that runs the `.ps1` beside it with Windows PowerShell 5.1 and `-ExecutionPolicy Bypass` for that one run (Windows' own *Run with PowerShell* obeys the execution policy, which refuses a script from a downloaded ZIP or, on many PCs, every script; no setting of the PC is changed). Windows may warn once that the file comes from the internet: *More info* -> *Run anyway*, or *Run*. An installer opens - *Welcome* -> *Dark Colony* -> *Dark Colony Ultimate* -> *Dark Colony Map Editor* -> *Finished*, with *< Back* / *Next >* / *Cancel*. The welcome page lists the three originals it **found beside the script** (`DC - Council wars/dc16.exe`, `DC - Council wars/ENGEXP16.EXE`, `Dark Colony - Map editor/maped.exe`) and offers the desktop shortcuts (ticked); each of the three option pages has "Patch <name>" (ticked), the original with its own *Browse* button, the screen resolution (the two game pages, kept equal because both games share `INTRF_HD`), the fix checklist with *Select all fixes* and the description of the highlighted fix. An original that is missing, already patched, changed or no Dark Colony exe at all puts a **big red box** on its page (and a red banner on the welcome page) with what was found and what is expected, *Select the correct file...*, *Download from our repository* (opens the file's GitHub page; the script downloads nothing) and where the original disc has it (`EXPENG\ENGEXP16.EXE` on the Council Wars CD, `DC\MAPED.EXE` on the Dark Colony CD; the Dark Colony CD's `DC16.EXE` is the August 1997 build, the fixes need the January 1998 update from the repository); that executable stays unpatched until the right file is chosen. So *Next >* three times and *Patch* once writes `Dark Colony.exe`, `Dark Colony Ultimate.exe` and `Dark Colony Map Editor.exe` beside the originals, and a shortcut of the same name to each on the desktop, starting in its game folder. *Inspect an exe* tells you which fixes any executable carries. Without the starter, from a PowerShell prompt in the repository folder:

```
powershell -ExecutionPolicy Bypass -File .\Apply-DarkColonyPatches.ps1
```

Command line, for the record (the same options work through the starter, e.g. `INSTALL.CMD -List`): `-All [-DesktopShortcut]` (all three, like the window), `-Original <exe> -All`, `-Original <exe> -Patches nocd,resolution,hdpaths`, `-List -Detail` (every single byte edit), `-Verify <exe>`; relative paths are taken from the current folder.

The fixes, in the order the script applies them: no CD (`nocd`: the 2025 bypass of the two menu tests - and, in Council Wars, of a third test that threw the player out of a running game - plus, since 18 Sep 2026, the removal of the whole CD path: the bypass alone only ignored the answer of the CD test, the game still read the drive letter from `HBNFUFL.A01`/`.A02`, opened `D:\dc\anim.dat` and ran a write test there at start-up, at every menu screen and in game, fell back to `D:\dc\<file>` for missing files and asked to "insert the CD", and it never asks Windows to fail such accesses quietly, so a not-ready drive D: - a card reader or USB/optical drive without a medium, a sleeping second hard disk - showed Windows' "No Disk" box behind the full-screen game or stalled it; now the HBNFUFL/CD-path block is jumped over, the probe and every CD fallback are disabled and the "insert the CD" message is replaced; the patched exes no longer need the `HBNFUFL` files), 1024x768 display (9 Sep 2026), interface data from `INTRF_HD` (14 Sep; the 30 path strings that make the exe read the 1024x768 files from `INTRF_HD/` so the stock files stay usable by the original exe), Windows pointer stays hidden (10 Sep), local memory pool 32 MiB (10 Sep), day/night clock hand re-anchored (13 Sep), two-monitor start-up hang fixed (13 Sep), for Dark Colony only the Classic movies under their own names (15 Sep; `Dark Colony.exe` plays `AVI/DCINTRO.AVI` and the campaign lists in `INTRF_HD/` name `DCAENDING.AVI` / `DCHENDING.AVI`, because Council Wars' own `INTRO/AENDING/HENDING.AVI` sit in the same folder) and the WAV files read from the game root, not `exp/` (`sounds`, 19 Sep; the Classic exe's sound loader still carried the expansion's `exp/` prefix, harmless while Classic had its own folder, but in the shared folder it played the Council Wars briefings for Classic missions 1-8 and the Council Wars water sound), and for Council Wars only the OZI MISSIONS menu mode (10 Sep). The third build the script knows is the map editor: `Dark Colony - Map editor\maped.exe` -> `Dark Colony Map Editor.exe` (until 25 Sep 2026 `maped_ozi_ns_v1.2.exe`) with four fixes (15 Sep 2026: block sets, team colour and allies, Healer row, close box), all dialog-resource bytes, no code. The last fix of all three builds is the **high-resolution icon** (`icon`, 25 Sep 2026): the images of `DC - Council wars/DC_HD.ICO` (16 to 256 pixels) in a new `.dcicon` section appended to the exe, whose resource directory also keeps pointing at the exe's own resources; the games' group gets id 101 as well, which their window asks for, so the taskbar shows it too. The 1024x768 fix needs the `INTRF_HD` fix and the rebuilt interface data that ships in this repository next to the exe. The script itself is generated from the Python patch tools in Dark-Colony-Server (`tools/gen_apply_script.py`), so it always matches the committed executables.
